# Recette, présentation et bilan

# 1. Qu'est-ce qu'une recette ?

Dans notre contexte, effectuer une recette signifie vérifier méthodiquement que ce qui a été produit correspond au besoin attendu.

Vous allez tester le site d'une autre équipe.

**Vous ne modifiez pas leur code pendant le test.** Vous notez les observations.

---

# 2. Checklist de recette croisée

## Fichiers

- [ ] `index.html` existe.
- [ ] `internet.html` existe.
- [ ] `web.html` existe.
- [ ] `securite.html` existe.
- [ ] les images éventuelles sont rangées dans un dossier identifiable.

## Navigation

- [ ] depuis l'accueil, toutes les pages principales sont accessibles ;
- [ ] depuis chaque page, il est possible de revenir à l'accueil ;
- [ ] aucun lien testé ne conduit vers un fichier absent ;
- [ ] les intitulés des liens sont compréhensibles.

## Contenu

- [ ] Internet est expliqué ;
- [ ] la différence Internet/Web apparaît ;
- [ ] client et serveur sont expliqués ;
- [ ] DNS est expliqué à un niveau accessible ;
- [ ] URL est expliquée ;
- [ ] HTTP est présenté comme un échange requête/réponse ;
- [ ] la page sécurité donne des conseils compréhensibles.

## HTML

- [ ] chaque page possède un `title` ;
- [ ] chaque page possède un titre principal ;
- [ ] les paragraphes sont structurés ;
- [ ] les listes sont utilisées correctement ;
- [ ] les images possèdent un texte `alt` ;
- [ ] l'indentation permet de relire le code.

## Retour au groupe

Écrivez :

### Deux points positifs

1. …
2. …

### Deux problèmes ou améliorations

1. …
2. …

Soyez précis. « C'est nul » ou « c'est bien » ne constitue pas un retour exploitable.

---

# 3. Correction par l'équipe

Récupérez la fiche de recette.

Pour chaque problème :

1. reproduisez-le ;
2. trouvez le fichier concerné ;
3. formulez une hypothèse ;
4. corrigez ;
5. retestez.

Ne corrigez pas un lien sans cliquer à nouveau dessus.

---

# 4. Présentation rapide

Votre groupe présente le site.

Préparez les points suivants :

1. Quel était votre objectif ?
2. Comment avez-vous organisé les pages ?
3. Comment avez-vous réparti le travail ?
4. Quelle difficulté avez-vous rencontrée ?
5. Comment l'avez-vous résolue ?
6. Qu'a réalisé ou vérifié chaque membre ?

Vous n'avez pas besoin de préparer un diaporama.

---

# 5. Challenge final de raisonnement

L'enseignant vous proposera plusieurs incidents simples.

Exemples :

### Situation A

Une page affiche correctement le texte mais une image est absente.

Que vérifiez-vous en premier ?

### Situation B

Le lien affiche « Formation » mais mène vers une erreur car le fichier demandé n'existe pas.

Où cherchez-vous ?

### Situation C

Un utilisateur arrive à joindre une adresse IP mais pas un service en utilisant son nom.

Quelle notion découverte lundi mérite d'être examinée ?

### Situation D

Le serveur indique que la ressource demandée n'existe pas.

Quel code HTTP célèbre avez-vous rencontré cette semaine ?
