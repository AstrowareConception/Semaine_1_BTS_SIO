# Mini-projet final

# Guide de survie numérique du nouvel étudiant en BTS SIO

## Contexte

Imaginez qu'un nouvel étudiant arrive en BTS SIO la semaine prochaine. Il n'a aucune connaissance technique et vous demande :

> « Internet, le Web, le HTML… tout ça est encore très flou. Pouvez-vous me préparer un petit site qui explique les bases ? »

Votre équipe va réaliser ce site.

---

# Organisation

Travail en petits groupes déterminés en classe.

Chaque membre doit contribuer réellement. À la présentation, chacun devra pouvoir expliquer ce qu'il a réalisé ou vérifié.

---

# Production attendue

Votre site comporte au minimum **quatre pages** :

```text
guide-survie-sio/
├── index.html
├── internet.html
├── web.html
├── securite.html
└── images/
```

Vous pouvez ajouter une page `glossaire.html` si votre équipe avance suffisamment.

---

# Page 1 — `index.html`

Elle doit accueillir le lecteur.

Contenu minimum :

- un titre principal ;
- un court texte expliquant le but du guide ;
- une liste des thèmes disponibles ;
- des liens permettant d'accéder aux autres pages.

---

# Page 2 — `internet.html`

Expliquez avec vos propres mots :

- ce qu'est un réseau ;
- ce qu'est Internet ;
- pourquoi Internet n'est pas seulement « le Web » ;
- le rôle général d'une adresse IP.

Ajoutez au moins :

- deux titres ;
- trois paragraphes ;
- une liste ;
- une image ou un schéma simple si une ressource adaptée est fournie ;
- la navigation vers les autres pages.

---

# Page 3 — `web.html`

Expliquez avec vos propres mots :

- navigateur ;
- client ;
- serveur ;
- DNS ;
- URL ;
- requête et réponse HTTP.

Vous pouvez utiliser un exemple concret :

> « Un utilisateur saisit l'adresse d'un site dans Firefox… »

Racontez ensuite les principales étapes avec une liste ordonnée.

---

# Page 4 — `securite.html`

Cette page reste volontairement introductive.

Présentez quelques **bons réflexes numériques généraux**, par exemple :

- ne pas communiquer son mot de passe ;
- utiliser des mots de passe robustes et adaptés ;
- se méfier des messages demandant une action urgente ;
- vérifier l'adresse d'un site ;
- effectuer les mises à jour proposées par les sources légitimes ;
- éviter de publier inutilement des informations personnelles.

N'inventez pas de conseils techniques avancés que vous ne comprenez pas.

---

# Page facultative — `glossaire.html`

Si votre équipe a terminé les quatre pages obligatoires, ajoutez un glossaire comprenant au moins dix termes parmi :

- Internet ;
- Web ;
- navigateur ;
- client ;
- serveur ;
- réseau ;
- IP ;
- DNS ;
- URL ;
- HTTP ;
- HTML ;
- fichier ;
- dossier.

Chaque définition doit être courte et reformulée.

---

# Navigation obligatoire

Chaque page doit permettre de revenir à l'accueil.

Idéalement, chaque page contient une navigation identique vers toutes les pages principales.

---

# Contraintes HTML

Votre site doit utiliser correctement ce que nous avons appris :

- structure HTML complète ;
- titres cohérents ;
- paragraphes ;
- listes ;
- liens ;
- au moins une image si les ressources disponibles le permettent ;
- `alt` pour les images ;
- commentaires utiles ;
- code indenté.

## Interdictions pédagogiques de cette semaine

Vous n'avez pas besoin d'ajouter :

- CSS ;
- JavaScript ;
- framework ;
- base de données ;
- formulaire fonctionnel ;
- code trouvé en ligne que personne dans l'équipe ne sait expliquer.

---

# Étapes de travail recommandées

## Étape 1 — Lire tout l'énoncé

Ne commencez pas à coder avant d'avoir compris ce qui est attendu.

## Étape 2 — Créer l'arborescence

Créez les fichiers et le dossier `images`.

## Étape 3 — Répartir le travail

Exemple :

- membre A : accueil + navigation ;
- membre B : Internet ;
- membre C : Web ;
- membre D : sécurité + vérification globale.

Adaptez selon la taille du groupe.

## Étape 4 — Harmoniser

Les pages doivent sembler appartenir au même site : mêmes noms dans la navigation, structure cohérente et vocabulaire compréhensible.

## Étape 5 — Tester

Cliquez réellement sur tous les liens.

## Étape 6 — Relire les contenus

Le site est destiné à un grand débutant. Une définition incompréhensible n'est pas une bonne définition, même si elle est techniquement savante.

---

# Critères de réussite

Le projet est réussi si :

- [ ] les quatre pages obligatoires existent ;
- [ ] toutes les pages s'ouvrent ;
- [ ] la navigation fonctionne ;
- [ ] les notions sont expliquées simplement ;
- [ ] les fichiers sont rangés ;
- [ ] le HTML est lisible ;
- [ ] les images éventuelles fonctionnent ;
- [ ] chaque membre connaît sa contribution ;
- [ ] l'équipe est capable d'expliquer au moins une difficulté rencontrée.
