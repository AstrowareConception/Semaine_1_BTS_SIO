# Objectifs pédagogiques de la semaine

## Une semaine de fondations

Cette première semaine n'a pas pour objectif de transformer un débutant en développeur. Elle doit installer un vocabulaire, des représentations correctes et quelques gestes techniques de base.

Un étudiant qui termine la semaine en étant capable de construire seul trois pages HTML reliées entre elles, de ranger correctement ses fichiers et d'expliquer simplement ce qu'est une requête Web a déjà accompli un travail important.

---

# Objectifs de connaissances

À la fin de la semaine, l'étudiant doit pouvoir expliquer simplement :

- ce qu'est un réseau informatique ;
- ce qu'est Internet ;
- pourquoi Internet et le Web ne sont pas synonymes ;
- le rôle d'un navigateur ;
- la notion de client et de serveur ;
- le rôle simplifié d'une adresse IP ;
- le rôle d'un nom de domaine ;
- le rôle simplifié du DNS ;
- ce qu'est une URL ;
- le principe requête/réponse de HTTP ;
- le rôle de HTML dans une page Web ;
- la différence générale entre HTML, CSS et JavaScript.

---

# Objectifs pratiques

L'étudiant doit progressivement être capable de :

- créer un dossier de travail ;
- reconnaître l'extension d'un fichier ;
- créer une petite arborescence de dossiers ;
- ouvrir un dossier dans Visual Studio Code ;
- créer et enregistrer un fichier ;
- afficher un fichier HTML dans un navigateur ;
- écrire une structure HTML élémentaire ;
- utiliser correctement des titres et paragraphes ;
- créer une liste ;
- créer un lien ;
- afficher une image locale ;
- comprendre un chemin de fichier simple ;
- créer plusieurs pages et les relier ;
- repérer quelques erreurs courantes ;
- tester une réalisation à l'aide d'une checklist ;
- expliquer oralement son travail.

---

# Attitudes professionnelles recherchées

Dès cette première semaine, nous travaillons également des habitudes qui resteront importantes pendant les deux années :

- lire une consigne entièrement avant de commencer ;
- ranger ses fichiers proprement ;
- nommer clairement ses fichiers ;
- enregistrer fréquemment son travail ;
- ne pas masquer un problème ;
- décrire précisément un problème lorsqu'on demande de l'aide ;
- tester avant d'annoncer qu'un travail est terminé ;
- accepter la relecture d'un autre étudiant ;
- aider sans faire à la place de l'autre ;
- être capable de distinguer sa contribution personnelle dans un travail collectif.

---

# Positionnement par rapport au BTS SIO

La certification actuellement préparée est le **BTS Services informatiques aux organisations — RNCP40792**.

Cette semaine constitue une **initiation**. Elle ne signifie pas que les compétences du référentiel sont déjà maîtrisées ou validées.

Elle prépare cependant plusieurs dimensions du bloc commun **Support et mise à disposition de services informatiques**, notamment :

- la compréhension des ressources et services numériques ;
- la réponse progressive à des dysfonctionnements simples ;
- le développement de la présence en ligne d'une organisation ;
- le travail en mode projet ;
- les tests d'un service ;
- la constitution d'un environnement d'apprentissage personnel.

Le référentiel prévoit également des compétences de cybersécurité et de protection des données. Elles seront travaillées progressivement au cours de la formation ; elles ne sont volontairement pas condensées dans ces quatre premières journées.

---

# Un principe important : la progression avant la performance

Dans ce groupe, certains étudiants ont peut-être déjà créé des sites ou programmé. D'autres découvrent les extensions de fichiers et un éditeur de code.

Le socle du cours est construit pour les débutants. Les étudiants plus avancés disposent de challenges supplémentaires, mais ces challenges ne deviennent pas le nouveau rythme obligatoire du groupe.

Le véritable indicateur de réussite de cette semaine n'est donc pas :

> « Jusqu'où avons-nous réussi à aller ? »

mais plutôt :

> « Combien d'étudiants sont maintenant capables de refaire seuls ce que nous avons appris ? »
